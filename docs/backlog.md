# Відкладене

Рішення, які свідомо відклали. Коли береш пункт у роботу — прибери його звідси.

## Незавершені тренування

Кинуте тренування лишається в `workouts` з `finished_at = NULL`.
`GET /workouts/active` повертає останнє незавершене, тож головна вважатиме,
що юзер досі посеред тренування, навіть якщо воно тижневої давнини.

Варіанти (схиляємось до 1 + 3):

1. Питати юзера: на головній «Продовжити тренування від понеділка?» —
   продовжити або закрити (закриття — той самий `POST /workouts/:id/finish`).
2. Закривати автоматично: тренування без підходів за останні N годин
   вважається завершеним (умова в запиті active або при старті нового).
3. Не зберігати порожні: якщо при `finish` нема жодного підходу — видаляти
   тренування, щоб в історії не було пустих записів.

## Видалення акаунта на фронті

Бекенд готовий: `DELETE /auth/me` → 204, видаляє все юзера й стирає
refresh-куку. Лишилось: кнопка з підтвердженням (є `ConfirmSheet`), після
успіху — очистити auth-стор і кеш TanStack Query, перейти на /login.

## Офлайн-режим

Зараз кожен підхід одразу йде на сервер, при збої — червона плитка з повтором.
Далі: черга незбережених підходів в IndexedDB (outbox) з відправкою, коли
зʼявиться мережа. Основа вже є: id підходу генерує клієнт, вставка має бути
ідемпотентною (крок 7).

## Статистика

Окрема таблиця підсумків (обʼєм, рекорди) при `finish` плюс backfill з
`workout_sets` для минулих тренувань. Сирі дані вже зберігаються, тож це
додавання, не переробка.

## Сповіщення про кінець відпочинку

Звук/вібрація, коли екран заблокований, — лише через push і service worker.

## Закінчення рядків (CRLF / LF)

`core.autocrlf = true` у git і Prettier (пише LF) конфліктують: після
форматування git показує файли зміненими без змін у вмісті. Рішення —
`.gitattributes` з `* text=auto eol=lf`, окремим комітом.
